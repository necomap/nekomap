## 2026-09-30: 野良猫一覧の新設・ナワバリ管理ページの案内追加・地域猫の「行方不明」タグ

3つの要望に対応。

### 野良猫出没情報の一覧ページを新設（目撃情報・スポットと同じ構成）
- `DB/add_stray_region_and_delete.sql`（新規、**要Supabase SQL Editorでの実行**）: `stray_reports`に`prefecture`列を追加し、投稿者本人・管理者が削除できるポリシーを新設（従来は削除ポリシーが存在せず誰も削除できなかった）
- `pages/stray/index.js`（新規）: 野良猫出没情報の一覧。`RegionSelector`による都道府県フィルタ、新しい順、TNR予定バッジ表示、本人・管理者は削除可能。「＋追加」ボタンで投稿画面へ
- `pages/stray/new.js`: 里親募集等と同じ都道府県自動判定（位置確定時に自動入力、手動でも選び直し可）を追加。投稿後は地図ではなく一覧ページ（`/stray`）に戻るよう変更
- `components/Navbar.js`: メニューの「野良猫出没情報」のリンク先を一覧ページ（`/stray`）に変更（他の一覧＋追加ボタン構成と統一）
- `components/MapView.js`: 野良猫ピンのポップアップに「野良猫情報一覧を見る」リンクを追加

- `pages/territories/index.js`: ページ上部に案内文（「このページでは新規登録できません。地図ページの描画ツール（多角形アイコン）で範囲を囲むと登録できます」）と、地図ページへのボタンを追加

### 地域猫一覧に「行方不明」タグを追加（絞り込み可、登録者・管理者のみ設定可）
- `DB/add_cats_missing_status.sql`（新規、**要Supabase SQL Editorでの実行**）: `cats`に`missing`（真偽値）・`missing_note`・`missing_date`列を追加。新しいRLSポリシーは追加していない（既存の訃報機能がすでに登録者・管理者による`cats`のUPDATEで動作しているため、そのUPDATE権限をそのまま再利用する設計。訃報機能と同じ考え方）
- `pages/cats/[id].js`: 詳細ページに、登録者・管理者のみ表示される「行方不明として記録する」ボタン（状況・最終目撃日を任意入力）を追加。記録すると目立つバナー表示になり、「見つかった（解除）」でいつでも解除できる（訃報中の猫には表示しない）
- `pages/cats/index.js`: 一覧に「すべて／行方不明のみ」の絞り込みボタンと、行方不明の猫には一覧カードにバッジを表示
- 用語は「行方不明」を採用（迷子ペット関連で最も一般的な言い方のため）。「捜索中」など他の言い方に変更したい場合は教えてください

### 未実行・要確認事項
- **`DB/add_stray_region_and_delete.sql`・`DB/add_cats_missing_status.sql`は、まだSupabase SQL Editorで実行されていません。実行するまでは、野良猫一覧の削除・都道府県フィルタ、地域猫の行方不明タグはいずれも動作しません（列・ポリシーが存在しないため）**
- `cats`の「行方不明」機能は、既存の訃報機能と同じUPDATE権限（本人・同じチームのメンバー）を前提にしている。管理者がこれまで訃報記録を問題なく行えていたことから、管理者にもUPDATE権限がある前提で設計したが、もし管理者アカウントで「記録する」がエラーになる場合は、既存のUPDATEポリシーに管理者条件が含まれていない可能性があるため、別途ポリシー追加が必要になる

## 2026-09-30: 目撃情報・スポット一覧に都道府県フィルタを追加（他ページと同じUI・使い方に統一）

「地図からたどるのは忙しい人には手間なので一覧→地図の流れにしたい」「目撃情報の一覧にも、新しい順・都道府県絞り込み（他ページと見た目・使い方を揃えて）が欲しい」という要望に対応。前回追加した目撃情報・スポットの一覧ページ（`/sightings`・`/spots`）に、困りごと・里親募集・ボランティア募集・掲示板と同じ`RegionSelector`（都道府県絞り込みUI）を追加した。

なお、前回のSQL（`DB/add_own_delete_sightings_spots.sql`）は実行済みであることをユーザーが提示したポリシー一覧で確認済み。その際、`sightings`のSELECTポリシーが「本人と管理者のみ直接閲覧可能」に限定されていることも改めて確認できたため、今回の設計判断（下記）の裏付けとなった。

### DB: prefecture列の追加＋目撃情報専用の最小限RPC（**要Supabase SQL Editorでの実行**）
- `DB/add_region_filter_sightings_spots.sql`を新規作成
- `sightings`・`cat_spots`の両方に`prefecture text`列を追加（既存行はNULLのまま。新規投稿から入力される）＋検索用インデックス
- `sightings`は直接SELECTできない（RLSで本人・管理者限定）ため、一覧ページの地図座標は既存の`get_blurred_sightings`（座標を約100mぼかす）経由のまま維持し、そのロジックには一切手を加えていない。都道府県だけを返す新規の`get_sightings_prefectures()`（`id, prefecture`のみを返すSECURITY DEFINER関数、`anon`/`authenticated`に実行権限を付与）を追加し、一覧ページ側でidをキーに両方の結果をマージして使う設計にした（プライバシーに関わる座標情報を含む既存RPCの改修リスクを避けるため）
- `cat_spots`は非フード行が誰でも直接SELECT可能なため、`prefecture`列を追加するだけで既存の`select("*")`にそのまま含まれる（RPC不要）

### 投稿フォームに都道府県の自動判定を追加
- `pages/sightings/new.js`・`pages/spots/new.js`: 里親募集・ボランティア募集の投稿フォームと同じパターンで、位置（緯度経度）が確定するたびに`reverseGeocodeToPrefecture`で都道府県を自動判定し、手動でも選び直せる`<select>`を追加。投稿完了後は地図(`/map`)ではなく、新設済みの一覧ページ（`/sightings`・`/spots`）に戻るよう変更（一覧→地図の流れに合わせるため）

### 一覧ページに都道府県フィルタを追加（他ページと同じ見た目・使い方）
- `pages/sightings/index.js`: `RegionSelector`＋`useRegionFilter`を追加。`get_blurred_sightings`と`get_sightings_prefectures`を並行取得してidでマージ後、都道府県で絞り込み。並び順は変更なく新しい順を維持
- `pages/spots/index.js`: 同様に`RegionSelector`＋`useRegionFilter`を追加し、取得済みの`cat_spots`データ（`prefecture`列を含む）をそのまま絞り込みに使用
- デフォルトの表示地域は、他の一覧ページ（困りごと・里親募集・ボランティア募集・掲示板）と同じ判定順（①一時的な変更→②ログイン中ならアカウントの設定都道府県→③現在地から自動判定→④判定できなければ全国）で決まるため、見た目・挙動が完全に統一されている

### 未実行・要確認事項
- **`DB/add_region_filter_sightings_spots.sql`は、まだSupabase SQL Editorで実行されていません。実行するまでは、目撃情報・スポットの一覧で都道府県フィルタを選んでも絞り込みが効きません（列自体が存在しないため）**
- 既存の目撃情報・スポットの投稿（今回のSQL実行前のもの）は`prefecture`が未設定（NULL）のままなので、都道府県で絞り込んでも「全国」表示時と同様に常に表示される（フィルタで除外されない）仕様。過去分に都道府県を後から入力する手段は今回は用意していない

## 2026-09-30: マップのピンから各ページへのリンク整備・目撃情報とスポットの一覧ページ新設・困りごとへのコンタクト機能

「マップのピンから対象ページへ飛べる？」という質問を受けて調査したところ、「地域猫」（猫と紐付いている場合のみ）と「里親募集」のピンは既に詳細ページへのリンクがある一方、「困りごと」「野良猫」「スポット」「ナワバリ」のピンにはリンクがなく、特に目撃情報・スポットはそもそも一覧・削除の手段自体が存在しないことが判明。ユーザーからの追加要望（困りごとへのコンタクト機能、目撃情報・スポットの削除可否、それぞれの一覧ページ化）に基づき対応した。

### DB: 目撃情報・スポット登録を本人が削除できるように
- `DB/add_own_delete_sightings_spots.sql`を新規作成（**要Supabase SQL Editorでの実行**）
- 従来、`sightings`は管理者のみ削除可、`cat_spots`には削除ポリシー自体が存在せず、投稿者本人が自分の投稿を削除する手段がなかった
- `sightings`に「本人は削除可能」ポリシーを追加（既存の管理者削除ポリシーはそのまま維持、RLSのOR結合で共存）。`cat_spots`には「本人は削除可能」「管理者は削除可能」の両方を新設（`is_admin()`関数を使用）

### 困りごとマップにコンタクト機能を追加
- `pages/reports/index.js`: 投稿内容だけでは対応方法の判断が難しい場合のために、投稿者本人以外のログインユーザー向けに「投稿者にコンタクトを取る」ボタンを追加（掲示板・里親募集と同じ`getOrCreateDmRoom`によるチャット機能を利用）。対応状況（未対応/対応中）にかかわらず表示され、対応を決める前に投稿者へ質問できる

### 目撃情報・スポットの一覧ページを新設
- `pages/sightings/index.js`（新規）: 目撃情報の一覧。位置ぼかし処理を保証するため既存の`get_blurred_sightings` RPCを使用。猫と紐付いている場合は猫の詳細ページへのリンクを表示。「＋ 追加」ボタンで投稿画面へ。本人・管理者は削除可能
- `pages/spots/index.js`（新規）: スポット（トイレ・猫ハウス・フード場所）の一覧。フード場所は既存のRLS制限により登録者・認証済み団体以外には元々表示されない仕組みをそのまま利用。「＋ 登録する」ボタンで登録画面へ。本人・管理者は削除可能
- これにより、以前は投稿するだけで一覧を見返す手段がなかった目撃情報・スポットについて、困りごとマップと同様の「一覧＋追加ボタン」のイメージに統一

### ナビゲーションの導線変更
- `components/Navbar.js`: メニューの「目撃情報を投稿」「スポット登録」のリンク先を、それぞれ新設した一覧ページ（`/sightings`・`/spots`）に変更（困りごとマップと同じ、一覧ページ内に「＋追加」ボタンを置く構成に統一）

### マップのピンから各ページへのリンクを整備
- `components/MapView.js`のポップアップに以下のリンクを追加
  - 目撃情報ピン: 猫と紐付いている場合の詳細リンクに加えて、常に「目撃情報一覧を見る」リンクを追加
  - 困りごとピン: 「困りごとマップで詳細を見る」リンクを追加
  - スポットピン: 「スポット一覧を見る」リンクを追加
  - ナワバリ（ポリゴン）: 従来ポップアップ自体がなかったため新設し、「ナワバリ管理を見る」リンクを追加

## 2026-09-29（続き2）: 絵文字の全面置き換え（アプリ全体）

前回の絵文字統一作業（トップページと一部見出しのみ）では対応しきれておらず、「各ページの検索・地域の地球儀など、ほぼすべてのページに絵文字が残っている」との指摘を受け、アプリ全体を対象に絵文字の棚卸しと置き換えを行った。

### 対応方針
- 見出し・ボタン・ステータス表示など、JSXとして描画される絵文字はlucide-reactの対応アイコンに置き換え（サイズ12〜20px、周囲のテキストと色・余白を揃えて表示）
- `<option>`のテキスト・`placeholder`属性・`confirm()`/`alert()`のダイアログ文言など、アイコンを埋め込めない箇所は絵文字を削除
- カテゴリ・種別のラベル配列（例: `TYPE_LABELS`）は、複数の場面で使い回されるため統一して絵文字なしに変更
- 「←」「→」などの矢印記号は装飾的な絵文字ではなく通常の矢印表記として、変更対象から除外

### 主な修正箇所
- **`components/RegionSelector.js`**: 地域選択プルダウンの「🌏 全国」を「全国」に変更（ユーザー指摘の「地域の地球儀」はこのコンポーネントで、掲示板・困りごと・里親募集・ボランティア募集など地域絞り込みのある全ページ共通で使われていたため、この1箇所の修正で当該絵文字はアプリ全体から解消）
- **検索欄**: `pages/guide/index.js`・`pages/cats/index.js`・`pages/board/index.js`ほか、各ページの検索入力欄の虫眼鏡絵文字をlucide-reactの`Search`アイコン（入力欄内に配置）に統一
- **猫アイコン**: 一覧・詳細ページの猫写真プレースホルダー（🐱）を`Cat`アイコンに統一（`pages/cats/*`, `pages/adoption/*`, `pages/chat/*`, `pages/donate`, `pages/register.js`, `pages/admin/index.js` ほか）
- **位置情報関連**: 住所検索・地図選択まわりの📍✅を`MapPin`・`CheckCircle2`アイコンに統一（投稿系ページ全般）

## 2026-09-29（続き）: 絵文字統一・管理画面バグ修正・猫の代行一括登録・団体チーム機能

ユーザーからの4件の依頼をまとめて対応。

### 絵文字の統一
- トップページ（`pages/index.js`）の「NekoMapとは」欄で、以前の絵文字簡略化作業から漏れていた6つのアイコン（🗺️✂️👀🙋⚠️💝）をlucide-reactアイコン（Map/Scissors/Eye/Users/AlertTriangle/Heart）に置き換え
- `pages/cats/index.js`・`pages/board/index.js`・`pages/admin/index.js`で、見出しが`<h1>絵文字 タイトル</h1>`という生の絵文字表記のままだった箇所を、他ページと同じ`PageTitle`コンポーネント＋lucide-reactアイコンの表記に統一
- アプリ全体を検索し、絵文字が複数連続して装飾的に使われている箇所（「こてこて」感の原因になりやすい）がないことを確認済み。カテゴリ選択肢・通知設定など、単発の絵文字ラベルとして使われている箇所は既存の軽量な表記のため今回は対象外とした

### 管理画面が「確認中...」のまま開けない不具合の修正
- **原因**: 「管理者かどうか」を判定するRLSポリシーが`exists (select 1 from public.users u where u.id = auth.uid() and u.role = 'admin')`という、`users`テーブル自身を再度SELECTする書き方をしていた。加えて、2026-09-27の修正で`users`テーブル自体のSELECTポリシーにも同じパターンの判定（本人 or 管理者のみ閲覧可）が入ったことで、「usersを読む→管理者か確認するためにusersを読む→また確認する…」という無限再帰になり、PostgreSQLが`infinite recursion detected in policy for relation users`エラーを返すようになっていた。管理画面を開いた際に最初に行う「自分がadminかどうか」の確認がまさにこれに該当し、確認処理が完了せず「確認中...」のまま止まっていた
- **修正**: `DB/fix_admin_rls_recursion.sql`を新規作成。RLSを経由しないSECURITY DEFINER関数`public.is_admin()`を作成し、`users`テーブルのポリシーを作り直したうえで、他の「管理者のみ」ポリシー（posts/contacts/blacklist/reports/volunteer_applications/cats/sightings/adoptions）も全てこの関数を使うように統一（**要Supabase SQL Editorでの実行**）
- あわせて`pages/admin/index.js`の管理者確認処理にtry/catchを追加し、今後同種の問題が起きても画面が無限に固まらず、エラーメッセージが表示されるようにした（防御的修正）

### 猫の代行一括登録機能（管理画面「一括登録（猫）」タブ）

## 2026-09-28: 新機能「地域（都道府県）フィルタ」の追加
